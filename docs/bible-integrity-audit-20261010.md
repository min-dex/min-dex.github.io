# 성경 전 역본 읽기 전용 감사 — 2026-10-10

운영 13개 역본 404,259행을 사용자 제공 성경 XML ZIP과 대조했다.
검사 종료: 2026-10-10 13:00:11 KST. DB 내용은 변경하지 않았다.

## 결론

승인된 현대어 및 4개 역본 시편 표제 분리 결과를 반영하면,
모든 구절 주소·본문·소제목이 제공 원본의 기대 결과와 일치한다.
원본 대비 누락·추가·중복 주소·본문 차이·소제목 차이는 각각 0건이다.
모든 역본이 66권/1,189장이고, 비활성 행·잘못된 주소·대체문자 U+FFFD는 0건이다.
하지만 원본에 남아 있는 형식 문제와 기존 importer의 소제목 분리 한계가 있으므로
“전 역본에 문제가 없다”는 판정은 하지 않는다.

## 확인된 잔여 문제

1. **쉬운성경 시편 60:1**: 117자짜리 `<소제목>`이 본문 선두에 남아 있고
   section_title은 비어 있다. 기존 importer의 100자 제한 때문에 분리되지 않았다.
   앞서 적용한 대괄호 시편 표제 5건과는 별도 대상이다.
2. **우리말 요한계시록 17:1**: 원본부터 `<`로 시작한 소제목에 닫는 `>`가 없다.
   본문에 그대로 저장됐다. 신뢰할 수 있는 해당 역본 자료로 제목 경계를 확인한 뒤
   교정해야 한다. 이번 검사에서 경계를 추정해 수정하지 않았다.
3. **쉬운성경 사사기 20:23, 사무엘하 4:7, 열왕기상 8:42**: 원본과 DB 모두
   빈 본문이다. 바로 앞 절에 여러 절에 해당할 수 있는 긴 문장이 들어 있어
   합본 표현 가능성이 있다. 출판 원문 대조 전에는 본문 유실로 확정할 수 없다.
   현재 verse_end는 없고, 클라이언트의 번호 공백 추론도 빈 행 자체는 합치지 않는다.
4. **개역개정 신명기 6:19**: 원본과 DB에 독립 행이 없다. 18절에 대적을 쫓아내신다는
   문장이 포함되어 있어 합본 가능성이 있다. 클라이언트는 다음 행이 20절이면
   18절을 18–19 범위로 추론하지만, 별도 19절 행이 생기는 것은 아니다.

## 번호 차이와 제외한 후보

NIV의 16개 번호 공백은 제공 원본과 동일하다:
마 17:21, 18:11, 23:14; 막 7:16, 9:44, 9:46, 11:26, 15:28;
눅 17:36, 23:17; 요 5:4; 행 8:37, 15:34, 24:7, 28:29; 롬 16:24.
이를 import 과정의 누락으로 판정하거나 임의로 채우지 않았다.
현재 클라이언트는 번호 공백을 합본 범위로 추론하므로 원본의 생략과 합본을
명시적으로 구분하지 못한다. 표시 의미의 정확성은 후속 확인 대상이다.

현대인 등 역본별 총 행 수 차이는 제공 원본에도 동일하게 존재한다.
서로 다른 역본의 행 수가 같아야 한다는 기준은 사용하지 않았다.
NIV의 보충 표현과 한글KJV의 [주]/[하나님] 등은 소제목 후보에서 제외했다.
소제목 수 0은 해당 ZIP의 파싱 결과이며, 출판본에도 소제목이 없다는 뜻은 아니다.

ZIP에만 있고 운영에 없는 8개 역본은 운영 검증 대상이 아니다:
ASV, Darby, NAS, NRS, New King James Version, ReWebst, Webster, 일본어성경.
NRS의 빈 절 번호 2개도 운영 역본의 문제가 아니다.

## 방법과 한계

- `scripts/audit_bible_integrity.py`는 익명 읽기 키로 GET 요청만 수행한다.
- 모든 운영 역본을 페이지별로 읽고 전체 행 수와 안정적인 정렬을 확인했다.
  여러 HTTP 요청이므로 단일 트랜잭션 snapshot은 아니다.
- 역사적 importer의 문자 정규화·소제목 분리 규칙과 승인된 표제 수정을 반영해
  모든 주소의 text/section_title을 비교했다. 임의의 다른 내용 차이는 허용하지 않았다.
- 제공 ZIP과의 일치를 확인한 검사다. 출판사 원문 전체에 대한 교열이나
  모든 장의 UI·송출·개별 절 검색을 검증한 것은 아니다.
- 기계 판독 결과와 원본/운영 snapshot SHA-256은
  `docs/bible-integrity-audit-20261010.json`에 보관한다.
  후보의 성경 본문 발췌는 보고서에서 제외하고 주소를 보관했다.
- 독립 fixture 테스트 3개로 파싱, 승인 범위 제한, 누락/추가/중복/차이 감지를 검증했다.

재현:

```sh
python3 -B tests/test_bible_integrity_audit.py
python3 -B scripts/audit_bible_integrity.py '<성경 XML ZIP 경로>' \
  --output /private/tmp/mindex-bible-full-audit.json \
  --cache-dir /private/tmp/mindex-bible-audit-snapshots
```

검사 도구의 종료 코드 0은 수집 성공을 뜻한다. 문제 여부는 결과의 각 검사 항목으로 판단한다.
기존 적용 migration은 재실행하지 않았다. 이번 감사에는 운영 수정·push·배포가 없다.

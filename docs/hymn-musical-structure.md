# 찬송가 심층 검토와 마디 메타데이터

2026-10-20. 새찬송가 645개·통일찬송가 558개 버전 대상. 기존 전곡 가사 대조
기록과 마디·악구 전수 검증을 구분한다. 후자는 아직 완료되지 않았다.

## 메타데이터 기준

`data/hymn-musical-structure.json`은 version ID와 unit ID 기반 검토 대장이다.
검증한 수치·ID·가사 해시를 별도 runtime 자료로 배포하여 앱에 표시한다.
운영 DB memo에는 넣지 않는다. 현재 가사의 ID·해시·종류가 달라지면 재검토로 표시한다.
아래 날짜별 기록은 당시 현황이며 최신 진행 상태는 문서 마지막 기록을 따른다.

- 절 전체: 악보의 한 절을 한 번 부르는 기준의 대략적 마디 수.
- 블록별: 실제 저장된 빈 줄 구분에 대응하는 마디 수 배열. 예: `4+4`, `8+4+4`.
- 못갖춘마디와 마지막 불완전마디는 합산한 마디 상당량으로 표시한다.
- 후렴·아멘·Coda는 별도 항목으로 두며 절의 마디 수에 합산하지 않는다.
- 반복·도돌이표의 연주상 확장과 저장 송폼은 별개다. 이 값으로 송폼을 만들지 않는다.
- 낭송형은 예외로 분류한다. 미확인은 `null`이며 0이나 기본 4마디가 아니다.
- `textSha256`가 달라지면 기존 블록 매핑을 재검토한다.
- 근거 악보 경로·해시·검토 상태를 함께 보관한다. 글자 수로 마디를 추정하지 않는다.

## 이번 확인

기존 악보 경계 검토 근거를 구조화하고 새1·새151·통138·새585 악보를 다시 확인했다.
16개 버전의 본절 마디 정보를 대장에 넣었다. 새151·통138은 후렴도 4+4마디로 기록했다.
미측정 버전은 1,187개이며 이 중 새636·통548은 낭송형 예외다. 본절 수치가 있어도
Coda 등 다른 부분까지 모두 측정 완료라는 뜻은 아니다.

새585는 앞 블록 약8마디·뒤 블록 약10마디인 혼합 구성이다. 후반이 긴 것을 자동
오류로 보거나 4/8마디로 강제 재분할하지 않는다. 통138의 과거 3블록 후렴 제안은
현재 운영에서 이미 2블록으로 되어 있어 미해결 오류 목록에서 제외한다.

1203개 version identity, 현행 unit text hash, 근거 이미지 hash, 블록 개수와
마디 합계를 검사했다. 이번 작업에서는 가사·송폼·곡 연결·예배·운영 메타데이터를 수정하지 않았다.

## 성구 점검

[전수 점검 결과](song-scripture-audit-20261020.json). 654개 곡의 655개 성구가 모두
운영 주소 해석기로 인식되고 개역한글 장절 주소에 존재했다. 잘못된 장절·역순 범위·
동일 행 중복·성구 컬럼과 memo의 충돌은 발견하지 못했다. 새찬송가645장의 현재
성구는 보관 악보 검증 목록과 동일하다. 이는 이번에 645개 이미지의 성구를 다시
눈으로 대조했다는 뜻은 아니다.

6개 곡에는 약칭 또는 en dash가 남아 있다. 검색 해석은 정상이며 저장 표기 불일치다.
정규화 제안은 정식 책명+공백+장:절-끝절이며 범위/복수 참조를 축약하거나 삭제하지 않는다.
사용자가 요청한 이번 성구 작업은 파악이므로 운영 값은 바꾸지 않았다.

## 남은 작업

1. 1,187개 미측정 버전의 악보·실제 가사 경계를 대응하고, 이미 측정한 버전의
   후렴·Coda 등 미측정 부분을 확인한다. 반복·못갖춘마디·성부 응답을 따로 본다.
2. 새/통 판본별 가사 차이와 악구 경계가 검증된 범위를 대장에 명시하고,
   확인된 오류만 별도 교정 계획으로 만든다. 출력 보존 검증과 악보 대조를 혼동하지 않는다.
3. 버전별 마디 메타데이터의 저장·재열기·복제·삭제·가사 변경 시 무효화와
   목록 분류/표시를 구현·검증한 뒤 앱에 연결한다. 현재는 검토용 데이터 파일만 있다.


## 앱 표시 및 후속 대조 ·2026-10-20

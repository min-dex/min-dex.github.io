# 부서 달력·주보 입력 점검 · 2026-10-30

범위는 실제 DOM 입력과 앱 저장 어댑터이다. REST/RPC 응답만 격리했으며 운영
자료 변경·인쇄·송출은 실행하지 않았다. 전체 앱의 무결함 선언은 아니다.

| 확정 결함 | 처리 | 검증 |
| --- | --- | --- |
| 같은 달력 셀의 두 확정 저장이 동시에 전송됨 | 셀별 직렬화 | REST/RPC 지연 응답, 두 번 확정 |
| 앞 기도자 저장 실패 뒤 대기 입력의 비교 기준이 미확정 문구임 | 앞 요청 완료 후 서버 확정 캐시 기준 사용 | 실제 atomic 어댑터의 실패 후 다음 저장 |
| 공통 양식 저장 응답 때 속성창 재생성으로 커서가 사라짐 | 응답은 상태만 갱신 | node·focus·caret와 추가 문구 보존 |
| 자동 생성 주일 절기 참고행에서 입력이 조용히 사라짐 | 참고행 읽기 전용 | 부분 연도 부활주일, 실제 행 편집 유지 |

Chromium/WebKit에서 신규 save_order, bulletin_input_e2e,
generated_readonly 검사와 기존 calendar_late_failure, department_input_ime,
calendar_years, operations_live 검사를 통과했다. 달력 연도 전환·화면 재진입,
주보 예배 날짜 선택 복귀, 담당자와 여러 줄 입력, 실패 재시도, 한글 조합 및
Esc 취소를 포함한다. SOLID와 generated runtime hash 검사도 통과했다.

달력에서 실패한 값이 그대로 남아 있으면 원래 값으로 되돌리는 기존 정책은
유지한다. 그사이 새로 작성한 초안은 덮어쓰지 않는다. 아직 나오지 않은 11/1
찬양 콘티의 빈 슬롯은 정상이며 결함 목록에서 제외한다.

한계: 실제 운영 동시 사용자·불안정 회선·물리 키보드/모바일 IME·인쇄 결과는
이번 격리 점검의 검증 대상이 아니다. 배포 완료 여부는 배포 담당자의 exact SHA,
필수 통합 gate, Pages와 공개 파일 확인 결과를 별도로 따른다.

# 운영·교회력과 예배 목록 실시간 연동

2026-10-18. 운영 DB 스키마/권한은 바꾸지 않는다. 기존 하나의 Broadcast
채널을 공유하며 메시지는 식별자뿐이다. 원격 수신은 읽기 전용이다.

## 교회력

`CALENDAR_LIVE_FIELDS`는 현재 편집 가능한 기념/메모, 교회 일정, 부서별
기도·봉헌기도·설교 담당자, 성서일과와 전례 색상을 포함한다. 기존 네 개
연결 담당자는 atomic 연동을 유지하며, 나머지는 기존 셀 저장 성공 뒤
`calendarOnly` 알림을 보낸다. 실패한 저장은 알리지 않는다.

수신 시 DB 행을 읽고 표 전체를 재생성하지 않고 해당 셀의 textContent와
초기값만 갱신한다. 입력 포커스, 셀 저장 중/실패, 송출·음악·영상·모달은
보호하며 비동기 조회 중의 입력 revision/프로젝트/클라이언트 변경도 확인한다.
일반 일정 변경은 관련 예배를 다시 읽거나 저장하지 않는다. 같은 행에 연결
담당자 변경 알림이 겹치면 연결 담당자 갱신을 생략하지 않도록 병합한다.
일정 알림으로 읽은 행에서 실제 연결 담당자의 변경을 발견한 경우에도 예배
캐시를 무효화하여 담당자 알림이 유실되어도 연결 갱신을 놓치지 않는다.
재연결/복귀/60초 확인은 읽어 둔 날짜의 편집 필드만 대조한다.

## 예배 목록

`mindex.service-list-live.js`가 `content-committed`의 `service-list` 알림을
처리한다. atomic create/delete의 성공 영수증 뒤에 알리며 실패/미확정 요청은
알리지 않는다. ID만 전체 페이지 조회하여 구성원 변화를 확인하고 새 예배만
가벼운 목록 view로 읽는다. view 미지원 시 테이블로 읽는다. 네트워크/페이지
조회 실패를 빈 목록이나 삭제로 해석하지 않으며, 캐시로 삭제 여부를 판단하지 않는다.
기존 예배 aggregate, source document, atomic baseline, 가사·폼·음원은 교체하지 않는다.

홈/전체/부서별 목록과 사이드바를 갱신하되 현재 열린 예배·송출·주보 편집 DOM은
다시 그리지 않는다. 선택과 스크롤을 유지한다. 새 예배 입력 폼, 초안,
저장/로딩, 실패한 입력, 출력·재생 중에는 보류한다. 조회 완료 후에도 같은
보호 조건과 입력/선택/목록 객체/프로젝트 변경을 다시 확인한다.

현재 열어 둔 예배나 미저장 주보의 예배가 삭제되면 해당 로컬 문서와 목록 항목은
보호한다. 다른 화면으로 이동하고 초안 보호가 해제된 뒤 목록에서 제거한다.
예배 편집 화면의 삭제 알림은 기존 service-entry가 담당한다. 주보는 별도 안내한다.
보호된 삭제 재조회는 15초 간격으로 제한하며 새 알림/화면 전환은 빠르게 재확인한다.
숨겨진 브라우저/보호 상태에서는 조회를 보류하고, 복귀/재연결/60초 간격으로
예배 목록의 누락된 생성·삭제 알림을 복구한다.

예배 종류·고정 기본 항목과 참고자료의 후속 실시간 연동은 `content-realtime.md`를 따른다.
기록 보관함, 말씀 자료와 로컬 파일의 실시간 공유는 이 작업에 포함하지 않는다. 교회력 자체의 행 추가/삭제 UI도 새로 만들지 않는다.

## 검증

`tests/smoke_operations_live.py`: Chromium/WebKit 격리 프로필, 전체 편집 필드와
빈 값, 포커스/실패 셀, 성공/실패 저장 알림, atomic create/delete 알림,
열린 문서 보존/이동 후 삭제, 스크롤, 재생, 재연결, 조회 중 상태 변경,
조회 실패·1000행 초과 페이지·view 미지원, 수신측 DB 쓰기 0.
기존 department/content/worship realtime 테스트는 회귀 검증한다.
실제 외부 통신 확인은 합성 레코드와 별도 채널을 쓰며 운영 REST 쓰기를 차단한다.

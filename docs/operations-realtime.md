# 운영·교회력과 예배 목록 실시간 연동

2026-10-18. 운영 DB 스키마/권한은 바꾸지 않는다. 기존 하나의 Broadcast
채널을 공유하며 메시지는 식별자뿐이다. 원격 수신은 읽기 전용이다.

## 교회력

`CALENDAR_LIVE_FIELDS`는 현재 편집 가능한 기념/메모, 교회 일정, 부서별
기도·봉헌기도·설교 담당자, 성서일과와 전례 색상을 포함한다. 기존 네 개
연결 담당자는 atomic 연동을 유지하며, 나머지는 기존 셀 저장 성공 뒤
`calendarOnly` 알림을 보낸다. 실패한 저장은 알리지 않는다.

수신 시 DB 행을 읽고 표 전체를 재생성하지 않고 해당 셀의 textContent와
초기값만 갱신한다. 입력 포커스, 셀 저장 중/실패, 송출·음악·영상·모달은
보호하며 비동기 조회 중의 입력 revision/프로젝트/클라이언트 변경도 확인한다.
일반 일정 변경은 관련 예배를 다시 읽거나 저장하지 않는다. 같은 행에 연결
담당자 변경 알림이 겹치면 연결 담당자 갱신을 생략하지 않도록 병합한다.
일정 알림으로 읽은 행에서 실제 연결 담당자의 변경을 발견한 경우에도 예배
캐시를 무효화하여 담당자 알림이 유실되어도 연결 갱신을 놓치지 않는다.
재연결/복귀/60초 확인은 읽어 둔 날짜의 편집 필드만 대조한다.

## 예배 목록

`mindex.service-list-live.js`가 `content-committed`의 `service-list` 알림을
처리한다. atomic create/delete의 성공 영수증 뒤에 알리며 실패/미확정 요청은
알리지 않는다. ID만 전체 페이지 조회하여 구성원 변화를 확인하고 새 예배만
가벼운 목록 view로 읽는다. view 미지원 시 테이블로 읽는다. 네트워크/페이지
조회 실패를 빈 목록이나 삭제로 해석하지 않으며, 캐시로 삭제 여부를 판단하지 않는다.
기존 예배 aggregate, source document, atomic baseline, 가사·폼·음원은 교체하지 않는다.

홈/전체/부서별 목록과 사이드바를 갱신하되 현재 열린 예배·송출·주보 편집 DOM은
다시 그리지 않는다. 선택과 스크롤을 유지한다. 새 예배 입력 폼, 초안,
저장/로딩, 실패한 입력, 출력·재생 중에는 보류한다. 조회 완료 후에도 같은
보호 조건과 입력/선택/목록 객체/프로젝트 변경을 다시 확인한다.

현재 열어 둔 예배나 미저장 주보의 예배가 삭제되면 해당 로컬 문서와 목록 항목은
보호한다. 다른 화면으로 이동하고 초안 보호가 해제된 뒤 목록에서 제거한다.
예배 편집 화면의 삭제 알림은 기존 service-entry가 담당한다. 주보는 별도 안내한다.
보호된 삭제 재조회는 15초 간격으로 제한하며 새 알림/화면 전환은 빠르게 재확인한다.
숨겨진 브라우저/보호 상태에서는 조회를 보류하고, 복귀/재연결/60초 간격으로
예배 목록의 누락된 생성·삭제 알림을 복구한다.

예배 종류·고정 기본 항목과 참고자료의 후속 실시간 연동은 `content-realtime.md`를 따른다.
기록 보관함의 후속 연동은 아래 계약을 따른다. 말씀 자료와 로컬 파일의 실시간 공유는 포함하지 않는다. 교회력 자체의 행 추가/삭제 UI도 새로 만들지 않는다.

## 예배 목록 요약·기록 보관함 · 2026-10-18

확정된 atomic save/create/delete 뒤 service-list와 setlist-archive를 알린다.
예배 목록은 ID 외에 제목·날짜·종류·별칭·인도자·상태의 작은 메타데이터만 대조한다.
이미 로드된 문서/source_ref·가사·폼·음원·atomic baseline은 교체하지 않는다.
열린 예배/송출/주보와 초안은 보호하며 다른 행의 요약만 갱신한다. 선택·스크롤과
상세 편집 DOM을 유지하고 변경된 예배의 상세 캐시만 무효화한다.

mindex.archive-live.js는 기존 content transport/timer를 공유한다. 실예배
save_revision, 과거 import source/candidate updated_at을 페이지 단위로 대조하고
변경된 예배/과거 기록의 카드 메타데이터와 찬양 목록만 읽는다. 최초 안전한 대조는
전체 카드 메타데이터로 기준을 세우며 이후에는 변경분만 읽는다. 가사 본문·음원·
raw_payload 전체와 source document는 읽지 않는다. 새 연결이나 주기 타이머는 없다.

인도자 초안(저장 실패 포함), 포커스·모달·재생·송출·초기 로딩은 조회부터 보류한다.
조회 후에도 편집 revision/화면 필터/프로젝트/client/현재 archive 객체를 확인한다.
변경된 기록의 DB revision을 재확인하여 조회 중 저장된 혼합 스냅샷은 적용하지 않는다.
오류·불완전 페이지를 삭제로 간주하지 않고 기존 화면을 유지한다. 완전한 조회에서
확인된 삭제만 제거한다. 원격 수신은 DB 쓰기나 전체 서비스 reload를 수행하지 않는다.

기간·보기 방식·검색·스크롤을 유지하며 값이 같으면 다시 그리지 않는다.
기존 60초/복귀/재연결 복구를 공유하고 보관함이 비활성이면 조회하지 않는다.
현재 UI의 과거 기록 인도자 저장도 성공 후에만 알린다. 저장한 브라우저 역시
보관함 변경을 큐에 남겨 나중에 돌아왔을 때 반영한다. 외부 DB 도구의 수정에는
앱 알림이 없지만 source/candidate timestamp 변화는 다음 보이는 화면 대조로 복구한다.
실예배 수정은 기존 atomic save 경로를 사용해야 한다.

검증: smoke_operations_live.py의 기존 행 요약·문서 보존,
smoke_archive_live.py의 실예배/과거 기록·revision 복구·혼합 조회 거부·인도자 초안·
조회 실패/null·삭제·1000행 초과 페이지·알림 병합, smoke_worship_live.py의 확정 저장
알림과 실패 미전송, test_setlist_leader_edit.cjs의 기존 CAS/필드 보존을 확인한다.

## 교회력 한글 조합 키 보호 · 2026-10-30

교회력 셀의 한글 조합 중에는 Enter로 포커스를 빼거나 자동 저장하지 않고,
Esc로 입력을 초기값으로 되돌리지 않는다. isComposing과 keyCode 229를 함께
확인한다. 조합 완료 뒤의 Enter·Tab 저장과 Esc 취소는 기존 규칙을 따른다.

## 늦은 셀 저장 실패와 새 입력 · 2026-10-30

저장 실패 응답이 늦게 도착해도 그사이 새로 입력한 셀 내용·포커스·커서를
덮어쓰지 않는다. 실패한 요청 값이 여전히 보일 때만 기존 방식으로 원복한다.
취소 기준인 initialValue는 마지막 서버 값으로 유지하여 Esc와 다음 저장을
일관되게 처리한다. 저장 요청·atomic 연동·서버 값은 이 UI 보호로 바꾸지 않는다.

## 같은 셀 연속 저장 · 2026-10-30

같은 셀의 연속 확정 입력은 입력 순서대로 서버에 보낸다. 앞 요청이 실패해도
뒤 요청은 계속 처리하며, 부서 기도자 atomic 저장의 비교 기준은 앞 요청이 끝난
뒤의 서버 확정 캐시 값이다. 미확정 화면 문구를 비교 기준으로 사용하지 않는다.
대기 중인 요청도 저장 중으로 간주하여 연도 전환을 보류한다. 다른 셀의 저장은
독립적으로 진행하고, 프로젝트 연결이 바뀌면 이전 연결의 대기 요청은 보내지 않는다.
검증은 smoke_calendar_save_order.py의 실제 Enter/Tab·REST/RPC 어댑터를 사용한다.
Chromium/WebKit에서 연속 확정, 앞 요청 실패 후 기도자 저장, 늦은 응답 중 초안·커서,
Esc 취소, 저장 중 연도 전환 차단과 완료 후 화면 재진입을 확인한다. 운영 쓰기는 없다.

## 여러 민간연도의 교회력 · 2026-10-30

상단 연도 선택의 기본값은 현재 민간연도다. 선택 목록은 실제 조회 자료의 연도,
현재 연도 전후 1년, 선택 연도 전후 1년을 합친다. 부서 일과와 성서일과는 같은
연도 상태를 공유한다. 연도를 바꿔도 일정·담당자·성구를 복제하거나 생성하지 않는다.
실제 조회 자료가 없는 해는 선택기와 두 보기 탭을 유지하고 해당 연도의 빈 상태를
표시한다. 실제 행이 하나도 없는 해에는 계산상 절기 참고 행도 만들지 않는다.

초기 읽기는 날짜 하한 없이 date/id 순서로 기존 페이지 조회 함수를 사용한다.
진입·복귀 자동 읽기도 같은 전체 연도 범위를 읽는다. 이후 선택한 연도만 화면에
투영하며 같은 연도의 새 조회 snapshot은 캐시를 무효화하고 표 내부 스크롤을
보존한다. 연도 전환은 각 연도의 마지막 표시 월로 돌아온다. 현재 날짜/다가오는
주일 강조는 실제 날짜 비교를 유지하고 연도에 맞춰 움직이지 않는다.

민간연도와 교회력 주기를 구분한다. Year A/B/C는 기존 churchYearForCalendarDate와
adventStartDate로 계산하며, 연초 주기→대림절 이후 주기와 전환 날짜를 상단에
명시한다. 행의 교회력 연도도 같은 helper로 계산한다. 실제 절기명·담당·본문은
저장된 값을 유지하고 계산으로 다시 쓰지 않는다.

입력 중인 셀·실패한 입력·진행 중 저장이 있으면 연도 전환을 보류하고 기존 화면을
보존한다. IME 보호와 셀/atomic 저장 경로는 유지한다. 브라우저를 새로 여는 기본
연도는 현재 연도이며 연도 선택을 운영 데이터에 저장하지 않는다.

검증: smoke_calendar_years.py의 Chromium/WebKit에서 2025/2026/2027 양 보기,
1월·12월 및 대림절 경계, 자료 없는 2028, 원본 불변·연도별 표시 월·같은 연도
새 snapshot/scroll·입력 및 pending 보호·1005행 페이지 읽기를 확인한다.
기존 calendar_states/operations_live/content_entry_refresh 회귀도 함께 확인한다.

## 생성 절기 참고행의 입력 경계 · 2026-10-30

서버 자료가 없는 날짜에 계산해서 표시한 절기 참고행은 읽기 전용이다. 주일인
절기도 일정·담당자·성구 편집칸을 제공하지 않는다. 실제 서버 행은 기존 입력과
저장 경로를 유지한다. 참고행에서 입력을 받은 뒤 조용히 버리거나 실제 행을
자동 생성하지 않는다. smoke_calendar_generated_readonly.py는 부분 연도 fixture의
부활주일과 실제 일정 행을 양 보기·양 브라우저에서 확인한다. 운영 쓰기는 없다.
이 변경은 독립 READY이며 통합 필수 gate/Pages/공개 UI 확인과 구분한다.

# 찬양 DB·주보 저장본 실시간 연동

2026-10-18. `mindex.content-live.js`가 기존 department Broadcast 채널의
`content-committed` 이벤트를 공유한다. 메시지는 프로젝트·종류·레코드 ID와
중복 제거용 ID뿐이며 가사, 음원, 주보 본문을 전송하지 않는다.
같은 브라우저는 BroadcastChannel/storage, 다른 기기는 Supabase Broadcast를 쓴다.
운영 DB 스키마·권한 변경은 없다.

- 찬양 생성/저장/삭제와 주보·공통 양식의 성공한 저장 뒤에만 알린다.
  예배 편집에서 생성한 빈 곡도 포함한다. 실패한 CAS 저장은 알리지 않는다.
- 수신은 읽기 전용이다. 찬양은 곡·버전·가사·관련 곡을 별도 객체로 읽어
  모두 준비된 뒤 적용한다. 기존 사용자 버전 이름, 폼, 음원·타이밍 메타데이터를
  현재 정규화 경로로 보존한다. 기존 찬양 저장 자체는 여전히 여러 요청이며
  이 기능이 DB 트랜잭션을 추가하지는 않는다.
- 입력 포커스, 미저장 수정, 저장/로딩, 모달, 송출 창, 음악·영상 재생 중에는
  보류한다. 비동기 조회 후에도 편집 revision/선택/프로젝트/클라이언트와
  초안 fingerprint를 다시 비교한다. 찬양은 찬양 화면에서만 적용하여 예배의
  연결 가사나 진행 중인 슬라이드를 다시 생성하지 않는다.
- 선택한 곡/버전과 편집 화면 스크롤을 유지한다. 삭제된 선택 곡은 현재 화면을
  유지하고 알린다. 다른 곡의 추가·수정·삭제는 목록에 반영한다.
- 주보는 미저장 내용, 드래그, 양식/내용 모드, 인쇄 준비와 `afterprint`까지의
  인쇄 세션을 보호한다. 저장 revision이 달라진 경우에만 detached snapshot을
  적용하며 스크롤을 복원한다. 저장된 source snapshot과 명시적 빈 필드는
  기존 계약을 따른다. 조회 실패/원격 삭제는 현재 화면을 지우지 않는다.
- 공통 양식 편집 화면에서만 해당 양식 변경을 반영한다. 이미 저장한 주보에
  새 공통 양식을 자동으로 덮어씌우지 않는다.
- 재연결·온라인 복귀·창 복귀와 60초 간격으로 **현재 보이는 레코드**를 대조한다.
  전체 찬양 가사/음원 파일을 주기적으로 다운로드하지 않는다. 알림이 유실된
  비활성 레코드는 해당 레코드를 볼 때의 대조로 복구한다. 음원 자체는 이
  연동으로 재생하거나 다운로드하지 않는다.

검증: `tests/smoke_content_live.py`는 격리된 Chromium/WebKit 프로필에서
실제 수신/적용 경로, 버전·가사, 무변경 수신, 초안·포커스·재생 보호,
조회 중 입력, 재연결 복구, 주보 스크롤/인쇄 세션, 저장 성공/실패 알림을 검증한다.
인쇄 API만 모의 처리하며 시스템 인쇄창이나 fullscreen을 열지 않는다.
기존 주보 계약/편집 테스트와 예배 실시간 연동도 회귀 검증한다.

## 예배 공통 설정·참고자료 · 2026-10-18

같은 content-committed 채널에 service-settings / references 무효화를 추가한다.
예배 종류의 DB 메타데이터·고정 기본 항목과 참고자료의 링크·그룹·순서·활성 여부를
전체 페이지로 읽되, 소량의 설정 데이터만 조회한다. 예배 구조의 코드 기본값은
배포 대상이며 별도 DB 편집 기능을 새로 만든 것은 아니다.

실제로 성공한 종류별 저장 및 링크 생성/수정/삭제 뒤에만 알린다. 여러 종류 중
일부만 저장되어도 성공한 부분은 알림을 보낸다. 기존 저장 방식의 동시 수정 충돌
해결 정책은 바꾸지 않으며, 여러 사용자가 같은 필드를 저장하면 마지막 저장이 남을 수 있다.

수신측은 읽기 전용이다. 비활성 화면·미저장 초안·입력 포커스·모달·재생·송출·저장 중은
보류한다. 참고자료 편집기가 열려 있으면 삭제도 편집 완료 후 반영한다. 예배 종류는
열린 예배/송출/주보 문서가 있으면 보류하여 기본 항목 projection을 바꾸지 않는다.
기존 예배 본문·폼·가사·atomic baseline은 갱신하거나 저장하지 않는다.

조회 후 프로젝트/client/편집 revision/화면 선택/원본 설정 값을 재확인한다.
완전한 조회 실패나 불완전한 응답을 삭제로 처리하지 않는다. 변경이 없으면 DOM을
갱신하지 않고, 변경 시에도 스크롤과 선택을 유지한다. 새 socket/timer는 추가하지
않으며 기존 60초 복구·재연결·창 복귀를 공유한다. 숨김/보호 상태는 조회도 보류하고
알림은 종류별로 합쳐 중복 요청을 줄인다. 설정과 참고자료의 신호 누락 복구는 해당
화면이 안전할 때 수행한다.

검증: tests/smoke_shared_settings_live.py (Chromium/WebKit). 그룹/링크 변경·삭제,
초안/포커스/편집기/송출/조회 중 변경 보호, 스크롤, 무변경 DOM 유지, 재연결,
조회 실패와 저장 성공/실패 알림을 검사한다. 실제 기기 성능이나 동시 저장 충돌이
모두 해결됐다는 의미는 아니다.

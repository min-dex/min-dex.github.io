# 음원 박자 기준 가사 싱킹

실제 송출할 음원을 기준으로 가사·간주 화면을 맞춘다. 리허설 녹음은 가사와
반복 구조를 찾는 참고 자료다. 사람의 늦은 진입을 그대로 타임코드로 옮기지 않는다.
저장 계약은 [예배 저장 계약](worship-persistence-current.md)의 Worship-owned
audio bundle을 따른다.

## 1. 음원과 화면 확정

- 실제 재생할 파일의 해시·길이를 확인한다. 동명 파일이나 다른 편곡을 혼용하지 않는다.
- 예배 항목의 `음원·가사` (`audio_praise`)에 음원을 연결하고 로드가 끝난 뒤
  가사 화면 분할·반복·간주를 확정한다. 로드 중 입력한 cue는 음원 교체 완료 때
  초기화될 수 있다. 제목/담당자 화면과 실제 타이밍 대상 화면을 구분한다.
- 찬양 DB에 새 곡·버전을 만들지 않는다. 음원·직접 입력 가사·타이밍은 예배 소유다.

## 2. 실제 음원의 박자와 가사 진입 찾기

1. 리허설의 반주와 MR을 여러 구간에서 spectral correlation으로 정렬한다.
   일정한 녹음 시작 지연(offset)과 시간에 따라 늘어나는 drift를 구분한다.
   반복 반주 때문에 다른 마디로 맞은 저신뢰 구간은 제외하고 이웃 구간과 대조한다.
2. MR의 저역 킥·고역 타격음 onset 후보와 프레이즈 구조를 찾는다. 파일명 BPM이나
   전체 고정 격자만으로 맞추지 않는다. 템포 변화와 못갖춘마디(pickup)를 보존한다.
3. 가사 첫 발성 위치를 함께 확인한다. 타격음에 가까운 값이어도 한 박자 앞선
   잘못된 진입일 수 있다. 반복되는 같은 후렴을 비교하고, 가능하면 구간을 직접
   청음한다. ASR은 가사 위치 후보에만 사용하며 단어 timestamp를 정답으로 삼지 않는다.
4. 반주가 큰 리허설은 간주에서 녹음의 음색 차이를 추정하고 MR spectral power를
   뺀 잔차의 새 발성을 보조 근거로 쓸 수 있다. 직전 음절의 잔향과 새 발성을 구분한다.
   잔차에는 악기·잔향이 남으므로 완전한 보컬 분리나 독립 청감 검증으로 표현하지 않는다.
5. 확인된 가사 진입에 해당하는 MR 박자를 cue로 정한다. 가장 가까운 임의의 드럼
   타격점으로 자동 이동시키지 않는다. 불확실한 후보는 근거와 오차 범위를 남긴다.

카다로스에서 유용했던 분석 시작값: 정렬 4 kHz / STFT 256 / hop 40,
발성 잔차 16 kHz / STFT 1024 / hop 160 / 250–3000 Hz.
간주 여러 구간으로 반주 색깔을 추정하고 subtraction scale 1·1.5·2에서 결과를
비교했다. 국소 에너지 90백분위의 15%를 50 ms 유지하는 상승을 후보로 보되,
이 값들은 곡마다 다시 조정한다. 당시 추정 오차 약 0.05–0.15초는 보편적 보장이 아니다.

## 3. cue와 화면 표시 시각 구분

- 입력 cue는 음악적 진입(onset)이다. 현재 가사 화면은 cue보다 **1초 먼저** 표시한다.
  입력값에서 미리 1초를 빼면 이중 보정된다.
- 간주·사진 전용 화면은 입력 cue 그대로 전환한다.
- 가사·사진 순서·화면 분할·음원 연결이 바뀌면 fingerprint가 달라진다.
  이전 타이밍을 강제로 재사용하지 말고 재검증한다.

## 4. 예배 저장과 복원 검증

- `예배에 저장`으로 기존 atomic 항목 저장 경로를 사용한다. 음원 주소·가사·
  `config.audioTiming`을 함께 저장하며 로컬 캐시를 운영 원본으로 삼지 않는다.
- 저장 성공 후 다시 열어 전체 cue·활성 상태·음원 연결을 확인한다. 빈 로컬 저장소의
  독립 브라우저에서도 예배 조회만으로 복원되는지 확인한다. 이것과 물리적으로 다른
  컴퓨터에서의 검증은 구별해 기록한다.
- 긴 fingerprint를 포함한 현재 원문 JSON은 8000자 이력 미리보기 제한으로 자르지
  않는다. 저장 오류는 기존 원문 잘림 여부까지 확인하되 사용자 JSON 검증을 우회하지 않는다.
- 업로드 후 저장 결과가 불확실할 때 음원을 즉시 삭제하지 않는다. 실제 예배에서
  참조될 수 있으므로 저장 상태 확인과 재시도를 먼저 한다.

## 5. 최종 전체 재생

- `동기화 처음부터 재생`으로 자연 종료까지 건너뛰지 않고 확인한다.
  일반 `음악` 버튼은 파일 선택이므로 동기화 시작 검증에 혼용하지 않는다.
- 모든 가사·간주 진입, 간주 이후 복귀, 마지막 가사와 자연 종료를 확인한다.
  구간 seek 검증은 전체 연속 재생을 대체하지 않는다.
- 관찰 로그는 재생 시작 전에 준비한다. 음원 위치와 실제 표시 페이지를 함께 기록하고,
  관찰 도구를 나누어 실행할 때는 cue 경계를 피한다. 측정 공백과 반올림을 명시한다.
- 코드의 타임코드 전환 검증과 음악적 진입 검증을 별도로 기록한다. 관찰 주기나
  0.5초 비교 허용폭은 음악적으로 허용되는 오차 또는 정확도 보장이 아니다.
- 카다로스 최종 사례: 보정 후 264.19초 연속 재생, 가사 17개·간주 2개 순서 확인,
  자연 종료. 1,144개 관찰값 중 경계 ±0.5초 밖 페이지 불일치 0건. 상세 관찰이
  16.8초부터 시작해 첫 전환의 정밀 시각은 측정하지 못했다. 독립 청음·물리 송출
  장비 검증까지 완료했다는 의미는 아니다.

## 6. 완료 후 정리

- 이 작업 소유의 복사 음원·디코딩 WAV·분석 가상환경·중간 결과·중복 화면·상세
  polling 로그를 제거한다. 모델 캐시는 이 작업 전용이며 다른 작업이 쓰지 않을 때만 정리한다.
- 적용 cue와 파일 식별 정보, 짧은 최종 검증 결과 및 재사용 가능한 노하우만 남긴다.
  원본 파일·예배에 연결된 음원·실제 가사·유효한 회귀 테스트는 더미가 아니다.
- 운영 더미를 만들지 않는 격리 테스트를 우선한다. 다른 작업의 파일을 이름이
  비슷하다는 이유로 삭제하지 않는다. 공개 저장소에는 녹음·전체 운영 데이터·비밀을 올리지 않는다.

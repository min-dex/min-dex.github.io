# 찬양 선곡 정보와 이어 부르기

찬양 상세의 가사 위에 접을 수 있는 선곡 정보를 표시한다. 출처별 추천 키,
주제, 리듬·빠르기 분류와 이어 부르기 원문을 보존한다. 찬양 검색에 추천 키,
주제와 분류 설명을 포함한다. 추천 키는 악보 조성이나 실제 음원 설정을 바꾸지
않는다. MM 범위는 원문 분류의 설명이며 개별 곡의 확정 BPM이 아니다.

`record.metadata.metadata.selection_guidance`는 출처별 항목 배열이다.
각 항목은 `id`, `source`, `source_date`, `key`, `category`, `theme`,
`transition_note`, `next`를 가진다. `next`는 `song_id`, `title`, `key`,
`note`를 가진 확인된 대상의 목록이다. 원문에 있는 연결 순서/절/전환 설명은
`transition_note`가 기준이며 대상 목록을 자동 메들리나 실행 순서로 해석하지
않는다. 링크 클릭은 기존 찬양 열기 경로와 미저장 입력 보호를 사용한다.

대상 ID를 조회할 수 없으면 텍스트만 표시한다. 역방향 관계를 만들거나 기존
`related`/`same_song` 관계를 변경하지 않는다. 원본 제목·가사·폼·음원·예배
구성은 바꾸지 않는다. 다른 메타데이터 수정/저장 후에도 선곡 정보가 보존된다.

운영 반영은 공개 런타임 데이터 파일이 아니라 기존 native record의 revision
CAS 저장을 사용한다. 원문/전체 대조표/기존 곡 데이터는 비공개 로컬 근거로
보관하며 공개 테스트는 합성 자료만 사용한다. 동일 출처 행 ID는 재실행해도
중복 추가하지 않는다. 동명곡이나 다른 판본의 대응이 모호하면 반영을 보류한다.
문서의 최근 사용 색상과 옛 사용일을 현재 교회의 실제 사용 이력으로 가져오지
않는다. 현 단계 UI는 출처 기반 조회와 곡 이동이며 임의 자동 선곡/자동 연결,
악보 이조와 편집 UI는 포함하지 않는다.

검증: `test_praise_selection.cjs`, `smoke_praise_selection.py`가 기본 gate에
등록된다. 정규화/이스케이프/단방향/누락 대상/검색, compiled runtime 표시,
다른 정보 저장 뒤 보존, 실제 대상 클릭, 좁은 화면과 접기를 검사한다.

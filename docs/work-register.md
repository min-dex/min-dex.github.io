# 민덱스 진행 중 작업대장

상태 정리일: 2026-11-09. 이 대장은 찬양 데이터 정비와 저장·접속 현황 UI 후속 작업의 현재 인수인계 기준이다. 민덱스 전체 기능의 완료 선언이나 실시간 DB 집계가 아니다. 다른 담당의 설치본·현장 검증은 해당 담당 문서에서 관리한다.

새 작업을 시작할 때 이 대장의 상태와 근거부터 확인한다. 날짜별 문서의 과거 ‘미완료’ 문구만으로 완료된 작업을 다시 실행하지 않는다. 아래 수치는 마지막 검증 기록 기준이며, DB 변경 전 대상의 현재 존재·내용·참조를 재조회한다.

## 상태와 갱신 규칙

- **자료 대기**: 구현·배포가 아니라 곡 식별 또는 입력할 원자료가 부족하다.
- **선택 정비**: 가능한 개선이지만 결함 수정이나 필수 미완료는 아니다.
- **의도적 보류**: 사용자가 유지하기로 했거나 확정 근거가 부족하다. 새 근거 없이 변경하지 않는다.
- **배포 대기 / 운영 검증 대기**: 로컬 검사, 공개 코드 반영, 실제 운영 검증을 각각 구분한다.
- **완료**: 완료 근거와 보호 대상 확인을 남기고, 새 오류가 확인되기 전에는 다시 미결로 올리지 않는다.

작업을 바꾼 담당이 이 대장의 해당 행을 갱신한다. 상태·대상 수의 기준일·다음 행동·완료 조건·근거 위치를 함께 갱신하고, CURRENT/HANDOFF에 같은 목록을 중복 작성하지 않는다. 작업 승인 범위는 사용자 요청을 따르며, 대장에 적혔다는 이유만으로 DB 변경이나 배포가 승인되는 것은 아니다.

P01·P02·P03은 현재 저장 API와 호환되는 데이터 보완이면 UI 배포 없이 진행할 수 있다. 다만 DB 가사 변경은 다음 송출 준비 때 기존 예배의 출력에도 반영될 수 있다. 실제 예배 행을 저장하지 않았다는 사실만으로 출력까지 불변이라고 판단하지 않는다. 실제 예배·메들리·송폼·음원 타이밍 변경은 이 대장의 기본 범위에 포함하지 않는다.

U01의 공유 배포 담당은 설치본/공유 릴리스 담당, U02는 이 저장 개선 작업 담당이다. 배포 담당이 통합 SHA와 공개 완료를 전달하면 U02를 수행한다. 자동 완료 처리나 별도 중복 배포를 하지 않는다.

## 완료된 작업과 재실행 금지 경계

- 가사 오교정 이력의 남은 132건: 최신 자료 연결에서 131건 식별, 1건은 추출 흔적. 연결된 항목의 다른 단어 오류 0건으로 일단락. 통550은 성부 배분 차이로 판단하고 아멘 7회 유지. 모든 곡의 무오류를 보증한다는 뜻은 아니다. E06.
- 마라나타 빈 중복, 햇빛보다 더 밝은 곳 빈 중복, 난 예수가 좋다오 빈 기본 판본: 각각 완료 검증 기록이 있다. P01 목록에 다시 포함하지 않는다. E07.
- 숨긴 중복 9개와 예수! 우리의 슈퍼히어로! 숨긴 기본 판본: 연결 이전·삭제·재열기 검증 완료. 마지막 확인 목록의 숨김 0개. 추가 잔재가 생겼는지는 별도 조회 대상이며 추가 삭제 대상을 확정한 것은 아니다. E08.
- 곡 조회 시간 초과 보완: 운영 조회 13회 동일 payload 검증 완료. 과거 timeout을 현재 미해결로 재등록하지 않는다. 재발 시 새 요청·오류·시간 근거로 조사한다. E09.
- 혼자 연속 수정·저장: 테스트 예배에서 연속·교차 저장, 늦은 읽기, 재열기까지 검증하고 TEST 삭제 완료. U01/U02는 그 이후 UI 개선의 별도 배포·운영 검증이다. E10.

## 문서 역할

- 이 대장: 현재 남은 일·보류·완료 경계. 우선순위와 상태를 갱신하는 한 곳.
- [문서 지도](README.md): 기능 계약과 상세 문서의 입구.
- `CURRENT.md` / `HANDOFF.md`: 시작 안내와 기존 날짜별 인수인계. 긴 과거 기록은 근거 이력이며 자동으로 최신 상태를 뜻하지 않음.
- 기능 계약 문서: 앱이 현재 어떻게 동작해야 하는지. 작업대장이 계약을 대신하지 않음.
- `backups/` / `output/`: 원본·변경 전후·검증 영수증. 단순히 오래됐거나 미완료 문구가 있다는 이유로 삭제하지 않음.

이번 정리는 문서만 변경한다. DB·실제 예배·앱 설정·배포 상태는 바꾸지 않는다.
